# موقع عيادة د. سعيد — نسخة الإصلاح

React/Vite + Cloudflare Pages Functions + Supabase. كل المتصفحات تستخدم `/api/content` من نفس السيرفر. لا كلمات مرور افتراضية ولا إعدادات اتصال محلية بالمتصفح، ولا إعلان نجاح قبل تأكيد قاعدة البيانات.

## التشغيل المحلي

Node.js 24 وpnpm 11.25.0. انسخ `.env.example` إلى `.env` وأدخل القيم الحقيقية محليًا، دون رفع المفاتيح إلى GitHub أو المحادثة.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

افتح `http://127.0.0.1:3000` واجعل `PUBLIC_SITE_URL` مطابقًا له. غياب الإعدادات يظهر خطأ واضحًا ويمنع الحفظ؛ المحتوى الافتراضي وحده ليس دليلًا على جاهزية قاعدة البيانات.

## إعداد Supabase ونقل البيانات

1. خذ نسخة احتياطية من القاعدة والصور، وجرّب على staging أولًا.
2. شغّل `supabase-schema.sql` كاملًا داخل SQL Editor. قابل لإعادة التنفيذ؛ ينقل الحجوزات إلى جدول خاص، ويفضل تفاصيل نسخة settings الكاملة، ويقفل صلاحيات المتصفح على الجداول القديمة والجديدة. ينقل التقييمات غير التجريبية للمراجعة، ولا يحذف الصور القديمة.
3. أنشئ مستخدم إدارة في Authentication ببريدك وكلمة مرور جديدة قوية، وأكد البريد. ضع UUID الخاص به في `ADMIN_USER_ID`. غيّر كلمات المرور القديمة المكشوفة. عطّل التسجيل العام إن لم يحتجه مشروعك. لا توجد كلمة مرور جاهزة داخل هذه النسخة.
4. ضع `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` و`ADMIN_USER_ID` في `.env`. مفتاح الخدمة للخادم فقط؛ لا تستخدم معه بادئة `VITE_`.
5. لاستيراد تعديلات `site_settings.settings_json` القديمة، قبل أول حفظ في اللوحة الجديدة:

```sh
pnpm exec tsx scripts/import-legacy.ts
pnpm exec tsx scripts/import-legacy.ts --apply
```

الأول فحص دون كتابة؛ الثاني استيراد الحقول العامة المسموحة فقط. يتوقف إن وجد محتوى منشورًا بالفعل. لا يستورد كلمات مرور أو حجوزات إلى الوثيقة العامة. البيانات غير الصالحة تفشل بوضوح وتحتاج تصحيحًا قبل الاستيراد. راجع جدول المواعيد الجديد؛ المخطط القديم لا يحدد أيام العمل بشكل موثوق. دون استيراد يبدأ الموقع بالمحتوى العام المرفق من الأرشيف.

## النشر على Cloudflare Pages

هذا مشروع **Pages مع Functions**. رفع `dist` وحده بالسحب والإفلات لا يكفي لتشغيل API. استخدم Git integration من جذر المستودع المحتوي على `functions/` و`backend/` و`shared/`.

- Build command: `pnpm build`
- Build output: `dist`
- Node: `24`
- Root directory: جذر هذا المشروع
- Runtime variables: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_USER_ID`, `PUBLIC_SITE_URL`.
- ضع الأسرار كـSecrets في إعدادات Functions ثم أعد النشر.
- `PUBLIC_SITE_URL` هو الدومين HTTPS الأساسي بلا مسار. حوّل الدومينات البديلة إليه؛ العمليات المعدلة من origin مختلف تُرفض لحماية الجلسات.
- استخدم قاعدة منفصلة وحساب اختبار للـPreview، مع origin مطابق لرابطه. لا تستخدم بيانات المرضى في المعاينة.
- `_routes.json` يشغّل API والصفحة الرئيسية لبيانات المشاركة و`sitemap.xml`. لا تضف تحويلًا عامًا يجعل API يرجع HTML.

بعد النشر افتح `/api/content`: يجب أن يرجع JSON عامًا و`Cache-Control: no-store`. `NOT_CONFIGURED` يعني نقص المتغيرات؛ `DATABASE_UNAVAILABLE` يعني فشل الوصول أو عدم تطبيق المخطط. رجوع HTML يعني عدم نشر Functions بصورة صحيحة.

اختبار القبول على الدومين: غيّر النبذة والصورة من الإدارة، وانتظر نجاح الحفظ. افتح نافذة خاصة مستقلة: يظهر التعديل بعد تحميلها أو خلال دورة القراءة البالغة 15 ثانية في التبويب الظاهر. اختبر حجزًا وهميًا ثم احذفه. لا تعتبر النشر مكتملًا قبل هذا الاختبار.

## استخدام الإدارة

- كل تعديل مسودة حتى الضغط على «حفظ ونشر هذا القسم». العربية والإنجليزية حقول مستقلة.
- تعارض الإصدارات يرفض الحفظ القديم: نزّل المسودة، أعد تحميل القسم، ثم ادمج المطلوب.
- انتهاء الجلسة يفتح تسجيل الدخول فوق النموذج دون حذف المسودة. تغيير كلمة المرور من اللوحة يبطل كل جلسات الإدارة.
- المواعيد بتوقيت القاهرة وتُولّد من الأيام والساعات ومدة الموعد. الطلب ليس موعدًا مؤكدًا، ولا يرسل واتساب تلقائيًا.
- الحجوزات وبيانات المرضى خاصة بالإدارة. المخزن يعرض أحدث 2000 طلب كحد أقصى، وقد يخفض Supabase العدد بحسب إعداد حد API. التقييمات حتى 1000 سجل. قبل تجاوز هذا الحجم يلزم ترقيم صفحات/أرشفة؛ البيانات لا تُحذف بهذه الحدود.
- التقييمات لا تظهر قبل الاعتماد. القوائم الفارغة مدعومة.
- الأصل المرفق في `public/doctor-original.jpg` لا يُستبدل عند الرفع. الصور JPEG/PNG/WebP حتى 8MB، والمحتوى يحفظ URL فقط.
- الخصوصية والشروط تُركتا فارغتين لكتابة النص المعتمد من صاحب العيادة. المؤهلات والادعاءات والصور والمواعيد تحتاج اعتماده أيضًا.
- التنبيه للحجوزات الواردة من السيرفر أثناء فتح الموقع وظهور التبويب؛ ليس Push عند إغلاقه. الصوت حسب سماح المتصفح.

## صيانة الصور

تُنظف الرفعات غير المستخدمة عند مغادرة المحرر طبيعيًا. الإغلاق المفاجئ قد يترك ملفات؛ أمر الصيانة يفحص الصور المدارة غير المرتبطة الأقدم من 7 أيام. شغّله مع نسخة احتياطية ودون محررين نشطين:

```sh
pnpm exec tsx scripts/cleanup-images.ts
pnpm exec tsx scripts/cleanup-images.ts --apply
```

الأول يعرض العدد فقط، والثاني يحذف غير المرتبط بعد فحص المحتوى. لا يمس الأصل أو bucket القديم، ولا يحتاجه الحفظ العادي.

## التحقق

```sh
pnpm check
pnpm exec playwright install chromium
pnpm test:e2e
```

API والمتصفح يستخدمان مخزنًا وهميًا داخل `tests/` لا يدخل الإنتاج. SQL يختبر PostgreSQL عبر PGlite، بما فيه الصلاحيات وإعادة التنفيذ. الاختبارات لا تتصل بقاعدة الإنتاج؛ قبول Supabase وCloudflare الفعلي يبقى مطلوبًا عند النشر. `CHROME_PATH` اختياري لاستخدام Chrome مثبت. يوجد GitHub Actions للأنواع والاختبارات والبناء والمتصفح.

## الملفات

- `src/`: الواجهة العامة ولوحة الإدارة.
- `backend/`: API والجلسات وموصل Supabase الخاص بالسيرفر.
- `functions/`: نقاط دخول Cloudflare وبيانات المشاركة والفهرسة.
- `shared/`: عقد البيانات والمواعيد والمحتوى العام الافتراضي.
- `supabase-schema.sql`: المخطط والترحيل وقفل السياسات القديمة.
- `scripts/`: الاستيراد وتنظيف الصور بأوامر صريحة.

مراجع: [Cloudflare Pages Functions](https://developers.cloudflare.com/pages/functions/)، [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).
